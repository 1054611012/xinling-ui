## 代码生成编辑页「上级菜单无法选择」修复（src/views/tool/gen/genInfoForm.vue）
- 根因：项目 Vue 3.5.13 与 vue3-treeselect@0.1.10（为 Vue 3.0 编写）不兼容，点击选项无法回填，
  表现为上级菜单 Treeselect 选不中/点了没反应。
- 修复：用 Element Plus 原生 el-tree-select 替换第三方 vue3-treeselect（零新增依赖，全局注册已可用）。
  数据映射：menus 树 {menuId, menuName, children} -> el-tree-select 的 :props="{
    label: 'menuName', children: 'children' }"，value-key="menuId"，
   parentMenuId 存 menuId 数字，与后端一致。新增 check-strictly（可选父菜单）、
   clearable、filterable（可搜索）、:render-after-expand="false"。
  同步删除不再需要的 normalizer 函数与 treeselect 的两行 import。
- 构建验证：npm run build:prod 通过。注意未删除 package.json 里的 vue3-treeselect 依赖，
  因 user/menu/dept/ontology 页面仍在使用（它们同样有 Vue 3.5 兼容隐患）。

## 上级菜单修复「复现」——文件被外部回滚导致悬空引用
- 现象：用户反馈「上级菜单还是存在问题」。复查发现磁盘上 genInfoForm.vue 又变回 <treeselect> + 旧 import，
  但 normalizer 函数已被删除 -> template 里 :normalizer="normalizer" 成为悬空引用（函数不存在），
  上级菜单因此彻底失效。属"部分改动被回滚"的混搭坏状态（疑似 IDE 内旧副本保存覆盖 或 手动 undo）。
- 处置：重新完整应用 el-tree-select 方案（import 移除 + template 替换），并 grep 校验
  normalizer/Treeselect/treeselect/:options 均无残留。构建通过，且 vue3-treeselect chunk 已从产物消失。
- 重要经验：改 RuoYi-Vue3 的 vue3-treeselect 时，import / template / normalizer 三处必须同进同退，
  否则会留下悬空 normalizer 引用导致组件彻底不可用。另需提醒用户：IDE 打开旧副本会覆盖磁盘改动。
